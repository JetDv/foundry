# The question set

Five questions. Their answers map directly onto structure — the mapping is in the right column, and it is why these five and not others.

| Ask | What the answer becomes |
|---|---|
| What is the repeating unit of work — an episode, a client, a report, a person? | the form (`02` picks from this) |
| Walk me through one run, start to finish. Where do you stop and check something before continuing? | stage boundaries and human gates |
| What stays the same every run — voice, rules, brand, schema — versus what is new every run? | the factory/product split, i.e. `_shared/` vs `output/` |
| What does "done" look like? What artifact leaves the workspace? | the last stage's output, and the definition of done |
| Who else touches this, and what do they need to find without asking you? | routing table in `AGENTS.md` |

## How to run it

- **A few at a time.** Dumping all five reads as a form and gets form-shaped answers.
- **Follow the pauses.** When someone says "and then I usually just check that the numbers look right before I send it" — that is a gate, and it is worth more than the rest of the sentence. Ask what "look right" means.
- **Chase the always.** "It always has to have the disclaimer", "it always has to sound like our newsletter" — every *always* is a factory reference file waiting to be named.
- **Do not offer a shape.** If they ask what the folders will look like, say that comes next and keep asking.

## The question behind the questions

Before the brief is written, you need an honest answer to: **has this actually repeated?**

If the person has done this thing twice, or is describing something they intend to start doing, the correct output of this stage is a brief that says so. The ladder runs chat -> saved prompt -> folders. Building a workspace for a process that has not stabilized produces a structure that is wrong in ways nobody can see yet, and that is more expensive than no structure.

Say it plainly and let them decide. Recording it in the brief is doing the job, not refusing it.
